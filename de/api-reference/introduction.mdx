# API-Übersicht

Seemodo bietet API-Endpunkte für die Kernfunktionen der Plattform: Screen-Generierung, Bearbeitung, Flow-Erstellung, Sandbox-Verwaltung und Cloud-Services.

## Basis-URL

Alle API-Anfragen gehen an:

```
https://api.seemodo.app
```

## Authentifizierung

Anfragen benötigen ein gültiges Token als Bearer Token im Authorization-Header:

```bash
Authorization: Bearer <dein-token>
```

## Verfügbare Endpunkte

### Generierung

| Endpunkt | Methode | Beschreibung |
|----------|---------|-------------|
| `/api/generate-screen` | POST | Einen Screen aus einem Prompt generieren |
| `/api/generate-wireframe` | POST | Ein Wireframe-Layout generieren |
| `/api/generate-flow` | POST | Screen-Aufschlüsselung für Multi-Screen-Flows |
| `/api/edit-screen` | POST | Bestehenden Screen mit KI bearbeiten |
| `/api/enhance-prompt` | POST | Prompt mit KI verbessern |

### Sandbox

| Endpunkt | Methode | Beschreibung |
|----------|---------|-------------|
| `/api/create-ai-sandbox` | POST | Neue Sandbox-Umgebung erstellen |
| `/api/sandbox-status` | GET | Sandbox-Status und URL prüfen |
| `/api/sandbox-logs` | GET | Sandbox-Build-Logs abrufen |
| `/api/run-command` | POST | Befehl im Sandbox-Terminal ausführen |
| `/api/install-packages` | POST | npm-Pakete in der Sandbox installieren |
| `/api/kill-sandbox` | POST | Sandbox beenden |

### Cloud

| Endpunkt | Methode | Beschreibung |
|----------|---------|-------------|
| `/api/seemodo-cloud` | POST | Seemodo Cloud aktivieren oder verwalten |
| `/api/supabase-proxy` | ALL | Proxy-Anfragen an die Cloud-Datenbank |

### Hilfsfunktionen

| Endpunkt | Methode | Beschreibung |
|----------|---------|-------------|
| `/api/scrape-website` | POST | Website-URL für Inhalte scrapen |
| `/api/scrape-screenshot` | POST | Screenshot einer URL erstellen |
| `/api/extract-brand-styles` | POST | Markenfarben und Stile aus URL extrahieren |
| `/api/proxy-image` | GET | Bild-URL proxen (CORS umgehen) |

## Rate Limits

API-Anfragen sind je nach Plan limitiert. Bei Überschreitung: `429 Too Many Requests`.

## Fehlerbehandlung

Standard HTTP-Statuscodes:

| Code | Bedeutung |
|------|-----------|
| 200 | Erfolg |
| 400 | Ungültige Anfrage |
| 401 | Nicht autorisiert |
| 403 | Keine Berechtigung |
| 429 | Rate-Limit überschritten |
| 500 | Interner Server-Fehler |

Fehler-Antworten enthalten ein JSON-Body:

```json
{
  "error": "Beschreibung des Fehlers"
}
```
