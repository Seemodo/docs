# API Overview

Seemodo exposes API endpoints that power the platform's core features. These endpoints handle screen generation, editing, flow creation, sandbox management, and cloud services.

## Base URL

All API requests are made to:

```
https://api.seemodo.app
```

## Authentication

Requests require a valid authentication token passed as a Bearer token in the Authorization header:

```bash
Authorization: Bearer <your-token>
```

## Available endpoints

### Generation

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/generate-screen` | POST | Generate a single screen from a prompt |
| `/api/generate-wireframe` | POST | Generate a wireframe layout |
| `/api/generate-flow` | POST | Generate screen breakdown for multi-screen flows |
| `/api/edit-screen` | POST | Edit an existing screen with AI |
| `/api/enhance-prompt` | POST | Improve a prompt with AI |

### Sandbox

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/create-ai-sandbox` | POST | Create a new sandbox environment |
| `/api/sandbox-status` | GET | Check sandbox status and URL |
| `/api/sandbox-logs` | GET | Retrieve sandbox build logs |
| `/api/run-command` | POST | Execute a command in the sandbox terminal |
| `/api/install-packages` | POST | Install npm packages in the sandbox |
| `/api/kill-sandbox` | POST | Terminate a sandbox |

### Cloud

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/seemodo-cloud` | POST | Activate or manage Seemodo Cloud |
| `/api/supabase-proxy` | ALL | Proxy requests to the cloud database |

### Utilities

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/scrape-website` | POST | Scrape a website URL for content |
| `/api/scrape-screenshot` | POST | Capture a screenshot of a URL |
| `/api/extract-brand-styles` | POST | Extract brand colors and styles from a URL |
| `/api/proxy-image` | GET | Proxy an image URL to avoid CORS |

## Rate limits

API requests are rate-limited based on your plan. Exceeding limits returns a `429 Too Many Requests` response.

## Error handling

All endpoints return standard HTTP status codes:

| Code | Meaning |
|------|---------|
| 200 | Success |
| 400 | Bad request (invalid parameters) |
| 401 | Unauthorized (invalid or missing token) |
| 403 | Forbidden (insufficient permissions) |
| 429 | Rate limit exceeded |
| 500 | Internal server error |

Error responses include a JSON body:

```json
{
  "error": "Description of what went wrong"
}
```
